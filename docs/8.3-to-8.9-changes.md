# Walmart Invoice Exporter: 8.3 → 8.9

This inventory compares the shipped `v8.3-main` tag with the `v8.9-main` release
tag, covering the interim 8.4, 8.5 and 8.8 work included in 8.9. It describes
changes to the extension, not just the features featured in the store listing.

## New dashboard views and invoice details

- **Categories:** see item spending and its share by category; expand a
  category to see the products, quantities, purchase counts and spend. Search
  products, review uncategorized products and override an automatic category
  or restore the suggestion. Choices are stored locally by site and account.
- Categories prefer Walmart's department, then infer from the product name;
  uncertain suggestions go to review. The Walmart Services department is
  recognized in exports. Category budgets stay in one site's currency, and
  lines Walmart marks as returned are shown separately from item spend.
- **Missed items:** see unavailable and canceled lines, substitutions,
  weight-adjusted items and late deliveries. See affected orders, common
  items and recent events. Older invoices without these details are reported
  as missing coverage, not counted as having no issues.
- **Charged item details:** price per item, original “was” price, savings,
  comparison price (such as per ounce), department, return eligibility,
  substitution/weight-adjustment/return labels and extra price notes.
- **Order details:** overall status (including partly canceled), late
  delivery, filling store, return window and never-charged lines. These
  fields are optional on Walmart.com and Walmart.ca; missing details don't
  fail otherwise valid orders.
- The modern Excel and spreadsheet CSV layouts add columns for the new
  details after their existing columns. Excel adds a **Not Fulfilled** sheet
  when there are never-charged lines. Those lines stay separate from charged
  items and never inflate totals.

## Collecting, saving and retrying orders

- Walmart's “Robot or human?” page is recognized during history collection
  and invoice fetching. Runs stop instead of repeatedly hitting the check;
  finished orders are kept, and invoice retries in the same panel session
  slow down. The user completes the check on Walmart before retrying.
- A collection cut short by a human check or a history page that didn't load
  now says why it stopped, how many orders were kept and what to do next.
  The local AI bridge exposes the same stop reason and page.
- Fast collection preserves partial results and can continue via normal
  pagination after an API failure or repeated cursor.
- The redesigned Walmart invoice layout is supported, including current
  item/total rows, current delivery charges and matching order metadata from
  the page payload; temporary authorizations aren't used as final totals.
- Invoice reads recheck a slow or empty page before trying the alternate
  order URL. Validating the order number, usable item lines and total
  applies to live reads and saved-invoice fallbacks. Failed orders are
  listed for retry, and a completely failed combined export writes no file.
- Fully canceled orders are valid with no charged items. Unavailable and
  canceled lines aren't brought back from other page sections, including on
  Walmart.ca. Category labels without item arrays aren't treated as proof an
  invoice is empty. The order-card fallback also rejects unrelated numbers
  that aren't order IDs.
- Saving to the library now applies the configured timing. **Retry failed**
  repeats the save rather than starting a download.
- Saved Walmart invoices are refreshed on their first export after the
  extraction update. If Walmart won't refresh a usable saved invoice, the
  export identifies it as stale rather than silently using it.
- Notices distinguish missing optional information from unexpected failures.
  Reportable warnings show the affected orders by their last four digits,
  explain the reason and offer an optional prefilled report. A known missing
  per-payment amount or a refused refresh doesn't ask the user to file one.

## Payments, totals and export behavior

- Payment brands carried in logo alt text survive image blocking. Payment
  amounts are read from accessible rows despite layout/CSS changes, with
  Walmart's charge-history panel as a fallback when amounts are missing.
- A single tender uses the final invoice total rather than adding cumulative
  PayPal partial charges. Mixed PayPal splits are reconciled when the evidence
  supports it; ambiguous or inconsistent totals stay flagged. A missing
  allocation isn't guessed if it would be negative.
- Duplicate Walmart Cash/WMTRC entries are consolidated. The generic OTHER
  tender can be merged with a specific tender sharing the same masked card
  ending, fixing duplicate gift-card rows and charge-history matching.
- Promo codes, express (“3 Hours or Less”) charges and returns, refunds and
  other meaningful adjustments are preserved across spreadsheet exports and
  HTML/PDF receipts. Dedicated fields cover the named adjustments, and
  remaining ones retain Walmart's labels. Delivery fees use the charged
  amounts rather than discounts or crossed-out values.
- Excel and receipts label fully canceled orders as having no charged items.
  QuickBooks and Xero bank-import presets skip unknown and zero totals, so a
  canceled order doesn't become an empty transaction.
- Tracking numbers were removed **from Excel** (not from all formats).
  Spreadsheet hyperlinks and receipt barcode links are validated; CSV values
  with spreadsheet formula prefixes are neutralized even when obscured by
  whitespace or control characters.

## Dashboard, local storage and AI

- Dashboard and order lists use the current invoice total when available,
  preserve explicit zeroes and don't treat missing totals as real zeroes.
  Fully canceled orders don't pull down the average order value.
- Updates to an existing invoice refresh the dashboard; stale results can't
  overwrite a newer view. Large headline numbers shrink to fit their tiles.
- Invalid dates fall back to valid stored dates; rolling date windows clamp
  to the last valid day in shorter months. Totals and dates are used more
  consistently across the dashboard, trends and Year in Review.
- Invalid data-retention dates or windows no longer cause premature deletion.
- **Reset settings to defaults** also removes the opt-in for AI collection.
  The local AI bridge prefers current invoice totals, requires pairing before
  handling tool calls, rejects inherited tool names and ignores events from
  sockets it has already replaced.
- Embedded dashboard commands are accepted only from the actual parent frame.
  Reuse of Walmart request headers is restricted to the order-history endpoint
  and its expected operation. The extension adds no manifest permissions.

## Release and maintenance

- CI now gates branch releases on regression checks, including browser tests.
- Added a private capture sanitizer, offline invoice replay corpus and
  coverage for redesigned invoices, canceled lines, split payments, financial
  adjustments, stale data, export safety, category assignment and more. The
  test harness cleans up its profiles and download listeners.
- Updated audited development dependencies and pinned patched transitive
  versions; kept the release-age policy with narrowly scoped exceptions.
  One upstream advisory remained documented at the time of the audit.
- Added verification, capture-testing and reliability notes; repository
  instructions; and repeatable procedures for release checks and store media.
- Refreshed the store description, screenshots and tiles using a synthetic
  demo catalog. The replacement tour is listing media, not extension code.

Already present in 8.3: the original spending dashboard and inline invoices,
month drill-down, item price trends, fast collection and its filters,
multi-account data, the original MCP integration, light/dark themes and the
existing export format choices. The sections above describe what changed.
